# Сборка под Android (Capacitor)

Проект спроектирован под обёртку **Capacitor**. Ниже — шаги для получения APK.
Это отдельный этап: сначала убедитесь, что MVP работает в браузере (`npm run dev`).

## Предварительные требования

- Node.js 18+
- [Android Studio](https://developer.android.com/studio) с Android SDK
- JDK 21 — Capacitor и Android Gradle Plugin собирают release именно на JDK 21
  (на JDK 17 сборка завершается ошибкой)
- Переменные окружения: `ANDROID_HOME` (или `ANDROID_SDK_ROOT`) указывает на SDK

## Шаги

```bash
# 1. Установить Capacitor (если ещё не установлен)
npm install @capacitor/core @capacitor/cli
npm install -D @capacitor/android

# 2. Создать конфиг Capacitor (id приложения задайте свой)
npx cap init SelfCRM com.example.selfcrm --web-dir=dist

# 3. Добавить платформу Android
npx cap add android

# 4. Собрать веб-приложение
npm run build

# 5. Синхронизировать сборку с Android-проектом
npx cap sync android

# 6. Открыть в Android Studio и собрать APK
npx cap open android
```

В Android Studio: **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
Готовый APK появится в `android/app/build/outputs/apk/debug/`.

## Замечания по хранению

- Приложение использует локальное хранилище браузера, которое в Capacitor WebView
  **сохраняется между запусками** (для `android` — через штатный WebView с persistent storage).
- Если потребуется нативный SQLite, замените реализацию `KVStore` в `src/db/kvstore.ts`
  на `@capacitor-community/sqlite`, реализовав тот же интерфейс. Интерфейс приложения не изменится.

## Офлайн и относительные пути

- В `vite.config.ts` задан `base: './'`, чтобы ассеты корректно загружались из `file://`.
- Роутинг на hash-фрагментах — безопасен для WebView.

## Системная кнопка «Назад»

Аппаратная кнопка «Назад» (и жест «назад») работает как стрелочка в шапке приложения:
приложение подписывается на событие `backButton` плагина `@capacitor/app`
(`src/components/SystemBack.tsx`, правила перехода — `src/utils/back.ts`). Приоритет нажатия:

1. открытое модальное окно или меню сортировки — закрывается (событие `selfcrm:back`);
2. карточка клиента/заказа/товара, статистика — переход туда же, куда ведёт стрелочка;
3. разделы верхнего уровня (Клиенты, Заказы, Товары, Склад, Настройки) — на «Главную»;
4. «Главная» — подсказка «Нажмите «Назад» ещё раз, чтобы выйти», второе нажатие в течение
   2 секунд закрывает приложение (стандартное поведение Android).

Плагин `@capacitor/app` для этого обязателен: в Capacitor 8 ядро кнопку «Назад» не обрабатывает,
и без слушателя нажатие уходит в стандартный путь Android — приложение закрывается. После
изменения зависимостей выполните `npx cap sync android`, чтобы плагин попал в Android-проект.

## Маршрут и навигация

Кнопка «Маршрут» в карточке клиента открывает `geo:`-URI через `window.open(uri, '_system')`.
Capacitor передаёт такую ссылку операционной системе, и Android показывает системный выбор
приложения для навигации (Google Maps, Яндекс.Карты, 2ГИС и т.д.). Дополнительных
Capacitor-плагинов для этого не требуется.

Кнопка «Вызов» (и сам номер телефона) в карточке клиента открывает `tel:`-URI тем же
способом — `window.open(uri, '_system')`. Android передаёт ссылку в звонилку, поэтому
отдельный плагин звонков не нужен. В браузере используется обычный `tel:` на текущей странице.

## Файлы: экспорт данных и чек

Android-WebView **игнорирует скачивание по ссылке** (`<a download>` с blob-URL): нажатие
«Скачать» в настройках не давало никакого результата. Поэтому файлы отдаются так же, как
PDF-чек: пишутся во временный каталог приложения (`@capacitor/filesystem`,
`Directory.Cache`) и передаются в системное меню «Поделиться» (`@capacitor/share`), где
файл можно сохранить в «Файлы» или отправить себе. Так работает экспорт резервной копии,
копия до импорта и копия повреждённых данных (`src/db/backup.ts`, `downloadJson`).
В браузере те же кнопки по-прежнему просто скачивают файл.

## PDF-чек

Чек генерируется офлайн на устройстве (библиотека pdfmake, шрифт Roboto с кириллицей).
Модуль загружается лениво, поэтому pdfmake не увеличивает основной бандл приложения.
На Android PDF записывается во временный каталог устройства (`@capacitor/filesystem`)
и открывается системное меню «Поделиться» (`@capacitor/share`) — так файл можно отправить
в мессенджер, почту или сохранить. В браузере файл скачивается обычным способом.

## Ориентация экрана

Приложение зафиксировано в портретной ориентации (`android:screenOrientation="portrait"`
в `AndroidManifest.xml`) — горизонтальный режим отключён.

## Проверка обновлений

Кнопка «Настройки → Обновления → Проверить» запрашивает последний релиз из GitHub-репозитория
(`doc9830/SelfCRM`) и сравнивает его версию с текущей. Если доступна новая версия, приложение
предлагает скачать APK со страницы релиза (открывается в системном браузере).

## Ключ подсказок адресов (Дадата)

Ключ Дадаты в исходниках не хранится — он подставляется в сборку переменной окружения
`VITE_DADATA_TOKEN`:

```bash
# один раз: файл не коммитится (см. .gitignore)
printf 'VITE_DADATA_TOKEN=<ключ>\n' > .env.local
chmod 600 .env.local
```

Затем обычный порядок: `npm run build` → `npx cap sync android` → сборка APK. Без `.env.local`
приложение соберётся, но подсказки адресов будут работать только по локальной базе
(**Настройки → Данные → База адресов**). Ключ — клиентский, он остаётся внутри APK: так
приложение работает у пользователя без собственного ключа.

## Безопасность сборки

- `res/xml/file_paths.xml` отдаёт наружу только внутренний кэш приложения (PDF-чек и APK
  обновления). Не добавляйте туда внешнее хранилище без необходимости.
- `android:allowBackup="false"` — данные не выгружаются в облачный бэкап Google и не
  переносятся через `adb backup`.
- Перед установкой обновления `AppInstallerPlugin` сверяет имя пакета и SHA-256 отпечатки
  сертификатов подписи скачанного APK с установленным приложением.
- `android/selfcrm-release.keystore` и `android/keystore.properties` должны иметь права `600`
  и храниться вне git (уже в `android/.gitignore`). Обязательно держите резервную копию ключа
  отдельно от проекта: без него обновление поверх установленной версии невозможно.

## Релизная сборка (подписанный APK)

Порядок выпуска новой версии:

1. Поднимите версию одной командой (обновит `package.json`, `src/version.ts` и
   `android/app/build.gradle`; `versionCode` увеличивается на 1):

   ```bash
   npm run bump -- 1.3.1
   ```

2. Проверьте и соберите веб-часть, затем синхронизируйте её с Android-проектом:

   ```bash
   npm run typecheck
   npm test
   npm run build
   npx cap sync android
   ```

3. Соберите подписанный release-APK, указав **JDK 21**:

   ```bash
   cd android
   JAVA_HOME=/path/to/jdk-21 ./gradlew assembleRelease
   ```

   Реквизиты подписи лежат в `android/keystore.properties` (файл и `*.keystore` не коммитятся,
   см. `android/.gitignore`):

   ```properties
   storeFile=selfcrm-release.keystore
   storePassword=<пароль хранилища>
   keyAlias=selfcrm
   keyPassword=<пароль ключа>
   ```

   Если `keystore.properties` отсутствует, сборка не падает, но APK остаётся неподписанным
   (`android/app/build/outputs/apk/release/app-release-unsigned.apk`) и на устройстве не
   установится.

4. Готовый файл: `android/app/build/outputs/apk/release/app-release.apk`.
5. Создайте релиз на GitHub с тегом `v<версия>` (например `v1.0.6`), приложите APK и опишите
   изменения — приложение показывает это описание при проверке обновлений.

> Переменные окружения для терминала: `ANDROID_HOME`/`ANDROID_SDK_ROOT` — путь к Android SDK,
> `JAVA_HOME` — путь к JDK 21. Сборка release на JDK 17 завершается ошибкой.
